# TikCookie 团购券平台 · 中间件配置

> v4 · 2026-09-29 · MySQL + MyBatis-Plus + OSS · 教学实践最小交付版  
> 配套：[需求文档](需求文档.md)和[接口文档](接口文档.md)。这是待实施的配置与数据模型，不表示当前 GitHub 骨架已经迁移完成。接口文档保持原样；本文件中的 OSS ObjectKey 填入接口的 `fileId` 字段。

## 1. 服务放置与职责

| 位置 | 服务 | 说明 |
|---|---|---|
| ECS A（现有 2C4G） | Nginx、Vue 静态文件、单实例 Spring Boot、Redis、RabbitMQ | 对外只开 Web 入口；后端 8080 供受控访问 |
| ECS B（现有 2C4G） | MySQL、单节点 Elasticsearch | A 通过同一 VPC 私网连接；MySQL 数据和 ES 数据均挂持久卷 |
| 阿里云 OSS | 专用演示图片 Bucket | 后端上传，浏览器按返回 URL 读图 |

这是一种教学演示放置方式，不是容量保证。B 上 ES 与 MySQL 共用 4 GB，启动后检查内存、堆和数据库连接数；资源吃紧时优先降低 ES 堆/连接池并控制测试数据量，必要时调整 ECS。无需 K8s、MongoDB、FastDFS、额外文件服务器或应用多副本。两台 ECS 的数据库、Redis、MQ、ES 端口仅内网可达；不把密码写进文档、仓库或 Compose 明文示例。

| 组件 | 默认端口 | 应用中的实际用途 |
|---|---:|---|
| MySQL | 3306 | 5 张业务表、InnoDB 事务和库存 |
| Redis | 6379 | 验证码、频控、错误次数、token |
| RabbitMQ | 5672（管理台 15672） | 一条搜索同步队列和失败队列 |
| Elasticsearch | 9200 | 店铺、商品两类索引；可从 MySQL 重建 |
| Spring Boot | 8080 | API、Swagger、任务、上传 |
| Nginx | 80/443 | Web 静态文件、`/api` 反向代理 |
| OSS | HTTPS | 图片对象存储，不驻留 ECS |

服务具体镜像和客户端小版本在工程骨架落地时固定，并记录在锁定的构建/部署文件；不得照搬历史文档中的 MongoDB、FastDFS 和 IK 插件安装要求。本版只需 ES 自带的 `standard` 分析器，中文搜索验收用真实样例确认。JDK、Spring Boot、MyBatis-Plus 和 MySQL 驱动版本在后端 `pom.xml` 统一管理；MyBatis-Plus 使用对应 Spring Boot 代际的 starter，启用其分页插件时增加匹配版本的 JSQLParser 模块。

## 2. 配置清单

所有地址、账号和密钥由 ECS 环境文件或本地环境变量注入，提交 `.env.example` 时只放占位值。`DSS_` 是后端配置前缀，实际 `application.yml` 应映射到这些变量。A 到 B 使用私网主机名或 IP。

| 变量 | 必需 | 用途 / 示例形式 |
|---|---|---|
| `DSS_MYSQL_HOST`, `DSS_MYSQL_PORT` | 是 / 否 | B 私网地址 / `3306` |
| `DSS_MYSQL_DATABASE`, `DSS_MYSQL_USERNAME`, `DSS_MYSQL_PASSWORD` | 是 | `dss` / 应用专用账号 / 口令 |
| `DSS_REDIS_HOST`, `DSS_REDIS_PORT`, `DSS_REDIS_PASSWORD` | 是 / 否 / 是 | A 私网地址 / `6379` / 口令 |
| `DSS_RABBIT_HOST`, `DSS_RABBIT_PORT`, `DSS_RABBIT_VHOST` | 是 / 否 / 否 | A 私网地址 / `5672` / `/dss` |
| `DSS_RABBIT_USERNAME`, `DSS_RABBIT_PASSWORD` | 是 | vhost 内应用账号 |
| `DSS_ES_URIS`, `DSS_ES_USERNAME`, `DSS_ES_PASSWORD` | 是 / 依认证方式 | 例如 `http://<B 私网地址>:9200`；开启认证时填写账号密码 |
| `DSS_OSS_ENDPOINT`, `DSS_OSS_BUCKET`, `DSS_OSS_REGION` | 是 | Bucket 对应地域与 endpoint |
| `DSS_OSS_ACCESS_KEY_ID`, `DSS_OSS_ACCESS_KEY_SECRET` | 按凭据方式 | 演示环境可用最小权限专用 RAM 用户；实际值只在受控环境文件中 |
| `DSS_FILE_BASE_URL` | 是 | 演示图片的 HTTPS 公共读取前缀（末尾不带 `/`） |
| `DSS_INTERNAL_KEY` | 是 | 内部接口口令；未配置时全部拒绝 |
| `DSS_SWAGGER_ENABLED` | 否 | 本期默认 true，仅受控访问 |
| `DSS_JOB_ENABLED` | 否 | 实现完订单任务后设 true；单实例执行 |
| `DSS_SERVER_PORT` | 否 | `8080` |

参考配置片段（仅示例；占位符应由环境提供）：


单文件业务上限 5 MB 应在应用层验证并返回 `106003`；框架的整请求 10 MB 上限对应原接口文档的 HTTP 400 / `40000`。ES 认证如开启，需要给后端配置客户端凭据（必要时 CA 信任）。时区统一 `Asia/Shanghai`，数据库字段用 `DATETIME(3)`，API 按原接口文档格式输出。不要把 Elasticsearch 地址直接提供给浏览器。

## 3. MySQL 与 MyBatis-Plus

### 3.1 数据规则

- 数据库 `dss`，字符集 `utf8mb4`，所有表 InnoDB。五张表：`users`、`shops`、`products`、`orders`、`favorites`。本期**没有** `outbox_events` 表。
- 所有主键 `BIGINT AUTO_INCREMENT`，Java 用 `Long`，对外 JSON 统一字符串。金额用 `BIGINT` 分。店铺图片、套餐内容和使用规则用 JSON 列；MyBatis-Plus 的 JSON TypeHandler 映射实体，服务层检查数组元素结构。
- 普通商品 `stock = NULL`；抢购商品 `stock` 为 MySQL 权威库存。订单保存购买时商品名、店名、图片 ObjectKey、金额快照，避免之后商品修改影响历史订单。
- 应用账号只需对 `dss` 的 SELECT/INSERT/UPDATE/DELETE 权限。建表由单独管理账号执行。脚本只针对空库，不是 MongoDB 数据自动迁移或已有 MySQL 表结构的升级脚本；部署前备份旧数据。

### 3.2 空库建表脚本

保存为 `dss-init.sql` 由管理账号执行；不预置账号或商品。建表后另由组员调用内部接口创建演示数据。

```sql
CREATE DATABASE IF NOT EXISTS dss CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;

```

### 3.3 最小事务实现

- `@Transactional` 用在订单创建、支付、取消、退款和核销。支付/退款/取消/核销都只在订单原状态符合时更新；更新行数不为 1 即拒绝或忽略重复处理。同一事务完成订单与销量/库存变化。券码唯一性由 `uk_voucher_code` 兜底；若撞号，回滚并在**新事务**重试。
- 抢购下单在短事务内读取并锁定商品行（`SELECT ... FOR UPDATE`），检查上架、时间窗、剩余库存及该用户未取消订单数；扣一件库存，插入订单。取消抢购单按同一商品行顺序锁定，订单确为 `UNPAID` 才回补库存。此处只是最小正确性保护，不引入 Redis Lua、分布式锁或压力测试目标。
- 每分钟扫描 `UNPAID AND pay_deadline <= NOW(3)` 作超时取消；每分钟扫描 `UNUSED AND expires_at <= NOW(3)` 作到期退款。单实例运行，无需 Redis 任务锁。每批数量可限制；扫描任务与用户操作复用同一事务方法，重复处理不能重复加减。
- 需要自定义 SQL 实现商品行锁、条件状态更新和库存修改；MyBatis-Plus `BaseMapper` 用于普通 CRUD 和分页。应用不再依赖 Mongo Repository、MongoTemplate、MongoDB URI 或 Mongo 事务。

## 4. Redis

Redis 只存短期登录数据，丢失后用户重新登录；订单与库存不会丢失。统一 `dss:` 前缀，使用 `StringRedisTemplate`。

| key | TTL | 值和用途 |
|---|---|---|
| `dss:login:code:{phone}` | 5 分钟 | 6 位验证码；重发覆盖 |
| `dss:login:code:interval:{phone}` | 60 秒 | 发送间隔标记 |
| `dss:login:code:fail:{phone}` | 5 分钟 | 累计错误次数；第 5 次按接口码失效 |
| `dss:login:token:{token}` | 7 天，访问续期 | 用户 ID、昵称、头像等登录信息 |

验证码只在开发/受控演示日志中出现，不经外部短信网关。数据库 ID、抢购库存、已购计数都不放 Redis。本期不做热门商品缓存和多实例任务锁。Redis 账号或口令仅私网和环境变量配置。

## 5. RabbitMQ 与 ES

### 5.1 消息拓扑

RabbitMQ 建 vhost `/dss`、专用应用账号、持久化队列。后端数据库事务提交后发消息；只需要如下最小拓扑：

| 名称 | 类型 / 绑定 | 用途 |
|---|---|---|
| `dss.search.direct` | direct 交换机 | 发送 `shop.changed`、`product.changed` |
| `dss.search.sync` | 持久化队列，绑定上述两个 routing key | 单消费者顺序处理（并发数 1） |
| `dss.search.dlx`、`dss.search.dlq` | 失败交换机与持久化死信队列 | 处理失败时暂存，供组员检查 |

消息体示例：`{"type":"PRODUCT","id":"123"}`；店铺用 `SHOP`。消息只带类型和 ID，消费者查询 MySQL **当前**记录更新 ES；店铺变化时重建本店商品文档。MySQL 先提交再投递，消费者成功写 ES 后确认消息；失败拒绝并进入死信队列，避免无休止重试。此方案不保证 MySQL 与 MQ 原子提交；丢消息、死信积压或 ES 重启后执行全量重建。**不要把消费者读到的消息当作订单写入依据。**

### 5.2 索引定义和查询

创建 `dss_shop` 和 `dss_product` 两个索引；字段与 API VO 不必相同，返回时映射为接口文档的 `ShopHitVO`、`ProductHitVO`。使用 ES 内置分析器即可，无需安装 IK 插件。

| 索引 | 必需字段（类型） | 查询规则 |
|---|---|---|
| `dss_shop` | `id` keyword、`name` text、`address` text、`category` keyword、`cover` keyword、`businessHours` keyword、`createdAt` date | 关键词查店名/地址，分类过滤；无关键词按创建时间倒序 |
| `dss_product` | `id` keyword、`shopId` keyword、`name` text、`contentsText` text、`shopName` text、`shopCategory` keyword、`type` keyword、`status` keyword、`price` long、`soldCount` integer、`image` keyword、`flashStartTime`/`flashEndTime` date | 仅上架；关键词查名称、内容、店名；分类/类型过滤；按接口约定综合、销量、价格排序 |

`contentsText` 从 MySQL `contents` 中抽取条目名称组成；`image`/`cover` 仍存 OSS ObjectKey，响应 URL 用配置的图片前缀拼装。`createdAt` 和抢购时间的索引格式需与应用统一。`status=OFF_SHELF` 时仍可保留文档，但搜索必须过滤它。商品详情和剩余库存始终从 MySQL 查询，不以 ES 数据作为最终值。

初始建索引后，从 MySQL 遍历店铺和商品逐条写入 ES；提供一个**内部维护命令或仅部署方可执行的任务**来清空并全量重建，不新增公开 API。演示前及死信异常后运行一次。ES 查询失败按原接口文档返回 `107001`；更新后搜索结果允许短暂延迟。中文词组、排序、上下架和店铺改名用实际演示数据联调。

## 6. OSS 图片

- 建立独立 Bucket，仅放本项目演示图片。为保持接口中的稳定完整 URL，演示 Bucket 可设为**公共读、禁止匿名写**；只上传非敏感、可公开展示的头像/商品图。写入权限只给后端 RAM 身份（或专用最小权限 RAM 用户），不向前端发长期 AccessKey。
- 上传接口先校验文件非空、扩展名及实际内容类型（jpg/png/webp），单文件 5 MB；生成随机 ObjectKey，例如 `group1/M00/00/00/{uuid}.jpg`，通过 OSS SDK 上传。数据库保存 ObjectKey；`fileId` 返回该 key，`url` 返回 `${DSS_FILE_BASE_URL}/{fileId}`。任何既有 `fileId` 只作为标识，不作为前端可构造的密钥或本地路径。
- 应用只接受本服务上传的对象 key，禁止用户传入任意 URL 指向外部资源。对象上传成功但数据库写入失败时，教学版允许留少量孤立文件，部署人员定期清理。检查跨域访问或浏览器直接展示是否正常。
- 如以后改私有读 Bucket，则需新增安全的代理或签名 URL 有效期设计；那属于下一版，不在本次 32 接口和最小演示范围内。

## 7. Nginx、Swagger 与访问边界

Nginx 以 `/` 提供 Vue 构建物，`/api/` 反向代理到本机后端 8080，保留 `/api/v1` 原路径；例如：

```nginx
server {
    listen 80;
    server_name _;
    root /srv/tikcookie-web/dist;
    index index.html;

    location ^~ /api/v1/internal/ { return 403; }
    location ^~ /swagger-ui { return 403; }
    location ^~ /v3/api-docs { return 403; }
    location /api/ { proxy_pass http://127.0.0.1:8080; }
    location / { try_files $uri $uri/ /index.html; }
}
```

Swagger UI (`/swagger-ui.html`) 和 OpenAPI 描述 (`/v3/api-docs`) 不经 Nginx 对外转发；后端 8080 只给受控来源访问。组员通过受控方式使用 Swagger 并带 `X-Internal-Key` 操作内部接口。生产演示域名配置 HTTPS 后再开放到公网。图片 URL 指向 OSS，不通过 Nginx 代理。CORS 由 Nginx 同源入口解决。

## 8. 初始化、迁移与验收

1. 在空 MySQL 8.x 库执行第 3 节脚本；检查五张表、索引、应用账号权限和持久化卷。切换已有 MongoDB 部署时先备份；历史 Mongo 数据不是本脚本的输入。
2. 启动 Redis、RabbitMQ、MySQL、ES、OSS 配置后再启动后端；确认 Spring Boot 连接、Swagger 和内部鉴权。迁移代码依赖到 MyBatis-Plus + MySQL、OSS SDK，移除 MongoDB/FastDFS 类与连接配置。
3. 调内部上传/创建店铺/创建普通与抢购商品；检查库表、OSS 图片 URL、ES 两个索引的搜索结果；更改商品后观察 RabbitMQ 消费并查更新结果。
4. 依《接口文档》走登录、订单、模拟支付、券码、核销、退款、取消、过期任务和收藏。订单状态与库存/销量以 MySQL 为准；索引删掉后可全量重建。
5. 对照接口文档全量核对 32 个路径、请求/响应字段、业务码。接口文档不随本文件变更；若真实实现发现冲突，另走独立评审修改。

当前两个 GitHub 仓库的 README、`PROJECT_GUIDE.md`、`CONFIGURATION.md` 等可能仍写 MongoDB；将本方案落地到仓库时需通过任务分支和 PR 清理这些旧说明，再把本文件从 API 仓库同步到 Web 仓库。不要把目标配置写成“已经运行成功”。
