# 抢购使用指南

这是教学演示，不涉及真实付款或商家履约。以下说明后端规则，页面入口以实际演示版本为准。本轮未检查或修改前端。

## 购买

1. 使用演示负责人提供的地址登录。
2. 查看本轮正在抢购的商品，确认价格、库存和限购。列表是快照，不保证点击时仍有库存。
3. 提交后等待建单。受理和取得订单号不代表订单已创建。
4. 查到本人订单后，重新读取状态、金额和支付截止时间，再模拟支付。
5. 支付成功为待使用，可查看券码、申请模拟退款或在到期前本人“去使用”。

## 重试和查询

- 同一购买遇到断网或响应丢失，继续原请求，复用原 requestKey，不直接新建购买。
- 30 秒是预占请求期限，客户端停止等待不代表服务端已释放库存。
- NOT_CREATED 只表示当前未查到本人订单，不是最终失败。保留原订单号和请求标识，继续查本人订单。
- 主动使用新请求键可能形成另一笔订单。先确认旧结果，再决定是否再买。
- 不要清除未确认的购买记录、切换账号绕过限购或频繁重复提交。

## 取消、退款和用券

| 操作 | 规则 |
| --- | --- |
| 取消 | 仅待支付订单；成功后按幂等流程回补抢购库存、释放额度 |
| 退款 | 仅待使用订单；模拟退款，不回补抢购库存，也不释放限购 |
| 去使用 | 本人待使用且未到期订单；不用输入券码，使用后不能按待使用订单退款 |

默认支付期限从建单起 15 分钟，以订单 payDeadline 为准。后台取消可能延迟，但到期后不能支付。券到期可由任务执行模拟退款。不要仅凭页面提示认定成功，重新查询真实订单状态。

## 常见情况

- 没有商品：可能未开抢、结束、售罄、下架、暂停或不属于本轮。
- 未支付却限购：排队预占和待支付订单也占额度。
- 已退款仍限购：符合规则，退款不释放名额。
- 取消后不能再买：活动可能结束或商品不可售，缓存也可能等待核对。
- 重启后商品 ID 变了：启用抢购的启动会追加新轮，历史订单保留。

联系技术人员时提供环境、商品 ID、订单号、请求标识和异常时间。遮挡个人信息，不提供 token、密码或验证码。技术规则见 [FLASH_SALE.md](FLASH_SALE.md)。
