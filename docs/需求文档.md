# TikCookie 团购券平台 · 需求文档

> v4 · 2026-09-29 · 教学实践最小交付版  
> 配套：[接口文档](接口文档.md)（保持原文，不修改路径、字段、状态与错误码）和[中间件配置](中间件配置.md)。本文定义要做什么和怎样验收；中间件配置定义数据结构及连接方式。以下是**目标设计**，不代表 GitHub 当前骨架已经实现。

## 1. 项目目标和边界

TikCookie 是供 5 人小组完成的 Web 团购券教学展示项目：用户浏览店铺和商品、下单、模拟支付、获得券码，再由组员模拟核销。需要能在两台阿里云 ECS 上部署并反复演示完整链路。项目**没有并发或性能指标**，不做真实商业运营。

| 层次 | 选型 | 本项目用途 |
|---|---|---|
| 前端 | Vue 3，Nginx | PC 浏览器页面；Nginx 托管静态文件和转发 `/api` |
| 后端 | Spring Boot，MyBatis-Plus，Swagger/OpenAPI | 一个应用完成全部业务与接口 |
| 权威数据 | MySQL | 用户、店铺、商品、订单、收藏及库存 |
| 临时数据 | Redis | 验证码、发送间隔、登录 token |
| 消息 | RabbitMQ | 店铺和商品变更后通知搜索索引更新 |
| 搜索 | Elasticsearch | 商品与店铺关键词搜索、筛选和排序 |
| 图片 | 阿里云 OSS | 图片上传和公开展示；数据库只保存对象 key |

目前仅部署**单实例后端**，无需 K8s、分布式锁、秒杀削峰、Redis 库存、事务消息 outbox、独立微服务或管理后台。模块可按用户、店铺、商品、订单、收藏、搜索、文件组织，但在同一个 Spring Boot 进程里运行。MySQL 是业务事实来源；ES 索引可以从 MySQL 重建。

## 2. 接口范围与实现取舍

接口文档固定为 **32 个接口（25 个用户端、7 个内部接口）**。本期交付要让这 32 个接口均按照原文档工作，包括统一响应 `code/msg/data`、`/api/v1` 前缀、参数格式和业务码。接口文档里的 HTTP 501 / 50100 只表示当前骨架尚未实现，最终演示不能用 501 代替功能。

| 范围 | 最小实现 | 明确不做 |
|---|---|---|
| 账号 | 手机号验证码写开发日志，Redis 存 5 分钟验证码；新号自动注册；token 7 天滑动续期；资料和头像修改 | 真短信、密码找回、多角色系统 |
| 店铺商品 | 内部接口用 Swagger 录入和上下架；浏览分类、店铺、商品、首页商品流、抢购专区 | 商家后台、购物车、评价、推荐算法 |
| 交易 | 一单一件一券；普通下单和抢购下单同步入 MySQL；模拟支付、券码、取消、退款、超时取消、到期退款、内部核销 | 真支付、真退款、对账和财务清算 |
| 搜索 | ES 搜商品名、套餐内容、店名、地址；按接口约定筛选和排序 | 地理位置、复杂相关度算法 |
| 收藏 | 收藏店铺/商品、取消、查看列表和状态 | 分享和社交关系 |
| 图片 | 两个既定上传接口由后端写 OSS，返回 `fileId` 和可访问的 `url` | FastDFS、图片审核和复杂处理 |

**兼容说明**：《接口文档》的图片示例是历史 FastDFS 风格路径。接口字段保持 `fileId` / `url` 不变；本版的 `fileId` 是 OSS ObjectKey。为让示例形式也容易复用，上传时可采用 `group1/M00/00/00/{随机名}.{后缀}` 作为 ObjectKey；这只是 OSS 的路径字符串，不部署 FastDFS。示例域名、示例 ID 均不是固定返回值。

## 3. 角色与页面

| 角色 | 可做的事 | 入口 |
|---|---|---|
| 游客 | 浏览、搜索、发送验证码和登录 | 首页、分类/搜索、店铺/商品详情、登录弹窗 |
| 登录用户 | 下单及订单操作、收藏、修改资料、上传头像 | 下单/模拟支付、我的订单和券码、收藏、个人中心 |
| 项目组员 | 录入店铺和商品、上下架、上传展示图、模拟核销 | 仅内部接口和 Swagger；不做后台页面 |

内部接口只认 `X-Internal-Key`；用户接口只认 `Authorization: Bearer <token>`。外部 Nginx 不放行内部接口和 Swagger，组员经受控方式直连后端调用。前端按《接口文档》联调，不重新设计 API。

## 4. 业务规则

### 4.1 商品和展示

- 店铺按接口文档的 6 种分类录入。商品类型只有 `NORMAL` 和 `FLASH`；新建后上架。普通商品不记库存；抢购商品记录库存、开始和结束时间、每人限购数。
- 首页和店铺商品列表只展示上架商品；抢购专区展示进行中与即将开始且尚未结束的上架抢购商品。商品详情、首页、搜索各自使用接口文档规定的 DTO 与排序。
- `contents`、`useRules`、店铺图片数组保存为 MySQL JSON；服务端验证数据结构。金额用整数分；所有 API ID 用字符串；时间格式 `yyyy-MM-dd HH:mm:ss`，时区 `Asia/Shanghai`。

### 4.2 下单和券

| 事件 | 前置条件 | MySQL 中的结果 |
|---|---|---|
| 普通下单 | 上架的 NORMAL 商品 | 同步生成 `UNPAID`，记商品/店铺名、图片、价格快照；15 分钟支付截止 |
| 抢购下单 | 上架的 FLASH 商品；时间窗内、库存大于 0、未达到限购 | 同一事务检查并扣库存、生成 `UNPAID` 订单；返回订单 ID 后立即可查 |
| 模拟支付 | 本人的 `UNPAID` 订单，未过支付截止 | `UNUSED`，生成唯一 12 位数字券码，记录支付与到期时间，已售数加一 |
| 取消或超时 | 仍为 `UNPAID` | `CANCELLED`；若为抢购，库存加一，取消订单不再占用限购 |
| 用户退款或到期退款 | 仍为 `UNUSED` | `REFUNDED`，已售数减一；抢购库存不回补，限购名额不释放 |
| 核销 | 券码对应 `UNUSED` 且未到期 | `USED`；已使用券不能再退或重复核销 |

抢购限购计数包含 `UNPAID/UNUSED/USED/REFUNDED`，不包含 `CANCELLED`。状态变更、抢购库存、已售数写入一个 MySQL 事务；更新订单时检查原状态，避免重复点击造成重复加减。只需基本的数据库正确性，无需压测指标或大规模抢购设计。

下单截止按订单的 `payDeadline` 判断；定时任务每分钟扫描过期未付订单，并调用同一个取消方法。券过期后按 `expiresAt` 每分钟扫描 `UNUSED` 订单，执行模拟退款。支付接口即使扫描尚未运行，也必须拒绝过期订单；核销接口同理。RabbitMQ **不承担订单落单、支付或超时的正确性**。

### 4.3 搜索和图片

- 店铺/商品新增、修改、上下架以及商品销量变化后，MySQL 先提交，再发一条 RabbitMQ 搜索变更消息。一个消费者从 MySQL 读取最新数据更新 ES；店铺名称或分类改变时，还要刷新该店商品索引里的冗余字段。搜索不可用返回接口文档的 `107001`。
- 本期不做业务库与 MQ 的跨系统强一致；消息丢失或消费失败时，组员可运行一次“从 MySQL 全量重建 ES”的维护命令或任务。展示前执行重建并核对搜索结果。索引可以重建，订单和库存不能依赖 ES。
- 只允许 jpg/png/webp；单文件最多 5 MB；整个请求按接口文档的 10 MB 上限处理。前端先调上传接口取得 `fileId`，再将其写到头像、店铺或商品。后端持有 OSS 凭据，前端不持有。

## 5. 分工与交付顺序

团队共 **5 人：前端 2 人、后端 2 人、阿里云部署 1 人**。接口文档是唯一 API 对照，开发中如发现接口冲突，先在 PR 中提出，经小组确认后另行改接口文档；本次修订不改变它。

| 阶段 | 后端（2 人） | 前端（2 人） | 部署（1 人） | 可演示的验收 |
|---|---|---|---|---|
| 1. 基础与浏览 | Spring Boot/MyBatis-Plus、建表、统一响应、Redis 登录、内部店铺/商品录入、公开浏览、Swagger | Vue 3 工程、登录、首页、店铺与商品详情 | 两台 ECS 私网互通；MySQL/Redis/应用/Nginx；环境变量和测试数据入口 | 组员录入一店一商品，游客可浏览，用户可登录 |
| 2. 购买闭环 | 普通/抢购下单、模拟支付、订单查询、券码、取消/退款/核销、定时任务 | 下单支付、订单列表/详情、券码和操作按钮 | RabbitMQ、备份和部署脚本；验证后端重启后订单仍在 | 完成普通单及抢购单“下单→支付→出券→核销”；另验取消、退款与过期 |
| 3. 搜索与图片收尾 | ES 搜索与重建、RabbitMQ 搜索同步、OSS 上传、收藏、全接口核对 | 搜索/筛选、收藏、头像与图片显示、错误提示 | ES、OSS、HTTPS/受控访问、联调和演示环境 | 32 个接口无 501；改商品后搜索可更新，图片能显示，页面走通 |

分工可在两位后端、两位前端内部灵活调整，但每个阶段都要先明确接口调用与数据样例。后端仓库 `CLPS-BLAKE/tikcookie-api` 维护 API 和数据库脚本；前端仓库 `CLPS-BLAKE/tikcookie-web` 维护 Vue 页面。文档以 API 仓库为源，再同步到 Web 仓库。现有仓库说明仍有 MongoDB 字样，合并本方案时需同步清理相应架构与配置说明。

## 6. 最终验收清单

1. 空库按建表脚本初始化，不需要预置用户；用内部接口上传图片、录入店铺和普通/抢购商品，首页、分类、商品详情可见。
2. 验证码登录、新手机号注册、token 续期、退出和修改资料可用；未登录与错误内部口令返回接口文档规定的 401/403。
3. 普通单和抢购单同步返回可查询的订单 ID；抢购在时间窗外、库存不足、超过限购时返回正确业务码；取消未付抢购单回补库存。
4. 模拟支付生成券码，状态 `UNPAID → UNUSED → USED`；重复支付/核销不会重复计算；退款与超时/到期处理按第 4 节的状态规则执行。
5. RabbitMQ 有店铺/商品变更消息，ES 能搜到最新内容；模拟丢消息后，手工重建可以恢复索引。OSS 图能在页面正常显示。
6. 用户网页走通：首页 → 搜索/详情 → 登录 → 下单 → 模拟支付 → 订单券码；Swagger 与原《接口文档》的全部 32 个接口、字段和错误码对应，最终不返回骨架期 501。
7. GitHub 修改走任务分支和 PR，由至少一名组员评审；真实数据库密码、OSS 密钥及 `.env` 不进入仓库。无并发吞吐、K8s、真实支付验收。
