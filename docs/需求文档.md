# TikCookie 团购券平台 · 需求文档

> 配套：[接口文档](接口文档.md)、[中间件配置](中间件配置.md)、[实现进度](PROGRESS.md)。本次不修改接口路径、字段、状态或错误码。本文规定需求与验收，不是完成清单；已有业务代码与尚未完成内容以进度文档为准。

## 1. 项目目标和边界

TikCookie 是供 5 人小组完成的 Web 团购券教学展示项目：浏览店铺/商品、下单、模拟支付、出券、本人点击“去使用”。2026-10-08 已确认 ECS 规格为 2 核 4 GB，MySQL/Redis/ES/RabbitMQ 同驻 node1，后端已部署阿里云，Nginx/前端待部署；后端具体实例与是否同驻 node1 待记录，不沿用旧双 ECS 固定分工。最终需反复演示真实完整链路。项目**没有并发或性能指标**，不做真实商业运营。

| 层次 | 选型 | 本项目用途 |
|---|---|---|
| 前端 | Vue 3、Vite、Vant，Nginx | 已有移动风格页面原型；仍需验收 PC 浏览器布局，Nginx 托管构建物和转发 `/api` |
| 后端 | Spring Boot，MyBatis-Plus，Swagger/OpenAPI | 一个应用完成全部业务与接口 |
| 权威数据 | MySQL | 用户、店铺、商品、订单、收藏及库存 |
| 临时数据 | Redis | 验证码、发送间隔、登录 token |
| 消息 | RabbitMQ | 既有店铺/商品变更消息与失败队列保留；消费同步未完成，不是当前 ES 写入方 |
| 索引同步 | Logstash JDBC | 已部署并同步 MySQL 店铺/商品，按更新时间每分钟轮询 |
| 搜索 | Elasticsearch | 商品与店铺关键词搜索、筛选和排序 |
| 图片 | 阿里云 OSS | 图片上传和公开展示；数据库只保存对象 key |

目前仅部署**单实例后端**，无需 K8s、分布式锁、秒杀削峰、Redis 库存、事务消息 outbox、独立微服务或管理后台。模块可按用户、店铺、商品、订单、收藏、搜索、文件组织，但在同一个 Spring Boot 进程里运行。MySQL 是业务事实来源；ES 索引可以从 MySQL 重建。

## 2. 接口范围与实现取舍

接口文档固定为 **32 个业务接口（26 个用户端、6 个内部接口）**，另有公开代理读图实现补充，不混入原 32 条统计。本期让全部业务接口按约定工作，包括统一响应 `code/msg/data`、`/api/v1`、参数和业务码。当前收藏 4 个、搜索 2 个接口仍返回 HTTP 501 / 50100，最终演示不能用 501 代替功能。

| 范围 | 最小实现 | 明确不做 |
|---|---|---|
| 账号 | 手机号验证码写开发日志，Redis 存 5 分钟验证码；新号自动注册；token 7 天滑动续期；资料和头像修改 | 真短信、密码找回、多角色系统 |
| 店铺商品 | 内部接口用 Swagger 录入和上下架；浏览分类、店铺、商品、首页商品流、抢购专区 | 商家后台、购物车、评价、推荐算法 |
| 交易 | 一单一件一券；普通/抢购下单同步入 MySQL；模拟支付、券码、取消、退款、超时取消、到期退款、本人点击“去使用” | 真支付、真退款、内部券码核销、对账和财务清算 |
| 搜索 | ES 搜商品名、套餐内容、店名、地址；按接口约定筛选和排序 | 地理位置、复杂相关度算法 |
| 收藏 | 收藏店铺/商品、取消、查看列表和状态 | 分享和社交关系 |
| 图片 | 两个既定上传接口由后端写 OSS，返回 `fileId` 和可访问的 `url` | FastDFS、图片审核和复杂处理 |

**兼容说明**：《接口文档》的图片示例是历史 FastDFS 风格路径。`fileId` / `url` 不变；fileId 为 OSS ObjectKey：`group1/M00/00/00/{32 位十六进制随机名}.{后缀}`（ObjectKeys），不部署 FastDFS。现行配置为 Bucket 公共读、禁止匿名写，URL 默认直连 OSS；若改为私有读，可把图片前缀改到后端代理接口 `GET /api/v1/images/{fileId}`。前端直接使用返回 URL，不自行拼路径；只放可公开展示的图片。

## 3. 角色与页面

| 角色 | 可做的事 | 入口 |
|---|---|---|
| 游客 | 浏览、搜索、发送验证码和登录 | 首页、分类/搜索、店铺/商品详情、登录弹窗 |
| 登录用户 | 下单及订单操作、收藏、修改资料、上传头像 | 下单/模拟支付、我的订单和券码、收藏、个人中心 |
| 项目组员 | 录入店铺和商品、上下架、上传展示图、协助验收 | 仅内部接口和 Swagger；“去使用”由登录用户操作，不做后台页面 |

内部接口只认 `X-Internal-Key`；用户接口只认 `Authorization: Bearer <token>`。外部 Nginx 不放行内部接口和 Swagger，组员经受控方式直连后端调用。前端按《接口文档》联调，不重新设计 API。

## 4. 业务规则

### 4.1 商品和展示

- 店铺按接口文档的 6 种分类录入。商品类型只有 `NORMAL` 和 `FLASH`；新建后上架。普通商品不记库存；抢购商品记录库存、开始和结束时间、每人限购数。
- 首页和店铺商品列表只展示上架商品；抢购专区展示进行中与即将开始且尚未结束的上架抢购商品。商品详情、首页、搜索各自使用接口文档规定的 DTO 与排序。
- `contents`、`useRules`、店铺图片数组保存为 MySQL JSON；服务端验证数据结构。金额用整数分；所有 API ID 用字符串；时间格式 `yyyy-MM-dd HH:mm:ss`，时区 `Asia/Shanghai`。

### 4.2 下单和券

| 事件 | 前置条件 | MySQL 中的结果 |
|---|---|---|
| 普通下单 | 上架的 NORMAL 商品 | 同步生成 `UNPAID`，记商品/店铺名、图片、价格快照；15 分钟支付截止 |
| 抢购下单 | 上架的 FLASH 商品；时间窗内、库存大于 0、未达到限购 | 同一事务检查并扣库存、生成 `UNPAID` 订单；返回订单 ID 后立即可查 |
| 模拟支付 | 本人的 `UNPAID` 订单，未过支付截止 | `UNUSED`，生成唯一 12 位数字券码，记录支付与到期时间，已售数加一 |
| 取消或超时 | 仍为 `UNPAID` | `CANCELLED`；若为抢购，库存加一，取消订单不再占用限购 |
| 用户退款或到期退款 | 仍为 `UNUSED` | `REFUNDED`，已售数减一；抢购库存不回补，限购名额不释放 |
| 点击“去使用” | 本人的 `UNUSED` 订单且未到期；不接收券码 | `USED`；已使用券不能再退或重复使用 |

抢购限购计数包含 `UNPAID/UNUSED/USED/REFUNDED`，不包含 `CANCELLED`。状态变更、抢购库存、已售数写入一个 MySQL 事务；更新订单时检查原状态，避免重复点击造成重复加减。只需基本的数据库正确性，无需压测指标或大规模抢购设计。

下单截止按 `payDeadline` 判断；任务每分钟扫描过期未付订单，复用取消方法。券过期按 `expiresAt` 扫描 UNUSED，执行模拟退款。支付和“去使用”即使扫描未运行也必须拒绝到期订单。RabbitMQ **不承担订单落单、支付或超时正确性**。当前到期退款条件错误需修复；任务默认关闭，修复并回归后启用，不能把已有任务代码当成已验收。

### 4.3 搜索和图片

- 当前采用已部署的 Logstash JDBC 同步：MySQL 变更维护 `updated_at`，每分钟轮询店铺/商品写 ES；店铺改名/分类依据关联更新时间刷新商品冗余字段。负责人确认同步成功，店铺 5/5、商品 30/30，mapping 已核对；证据见 [Logstash 部署记录](LOGSTASH_SYNC.md)。Java 搜索 API 尚未实现，查询失败按既定 `107001` 处理的规则不变。
- RabbitMQ 发布与消费者入口保留，但 Java 消费同步/全量重建仍是桩，不作为当前同步链路。Logstash 不保证强一致，不捕获物理 DELETE；故障需按维护说明重放，清理残留/修复 mapping 另行维护。订单、库存以 MySQL 为准；未来启用 MQ 写 ES 前明确写入方切换。
- 只允许 jpg/png/webp；单文件最多 5 MB；整个请求按接口文档的 10 MB 上限处理。**头像**可以直接把图片交给 `PUT /users/me/avatar`，由后端一步完成上传与写库；**店铺图、商品图**仍由前端先调上传接口取得 `fileId`，再将其写到店铺或商品。后端持有 OSS 凭据，前端不持有。

## 5. 分工与交付顺序

团队共 **5 人：前端 2 人、后端 2 人、阿里云部署 1 人**。接口文档是唯一 API 对照，开发中如发现接口冲突，先在 PR 中提出，经小组确认后另行改接口文档；本次修订不改变它。

| 阶段 | 后端（2 人） | 前端（2 人） | 部署（1 人） | 可演示的验收 |
|---|---|---|---|---|
| 1. 基础与浏览 | 已有基础/登录/录入/浏览代码，补联调与回归 | 已有 Vue/Vant 页面，移除假登录、接真实首页/详情与 ID | 核对 node1 四种中间件连接；确定应用/Nginx 位置、环境与数据入口 | 组员录入一店一商品，游客可浏览，用户真实登录 |
| 2. 购买闭环 | 已有交易代码，修复到期退款、回归库存/状态/重复操作 | 接真实下单/支付、列表/详情、券码、取消/退款/去使用 | 登记已部署后端；部署 Nginx/前端，核对 node1 资源/备份/持久化；重启后订单仍在 | 普通/抢购“下单→支付→出券→去使用”，另验取消/退款/到期 |
| 3. 搜索与图片收尾 | 实现 ES 查询、收藏；明确 MQ 消费及维护职责，验收 OSS | 接搜索/筛选、收藏、资料/头像/图片、失败提示 | Logstash 同步已确认；补恢复/资源证据，维护 ES/MQ、OSS、HTTPS 与发布记录 | 32 个业务接口无 501；搜索更新、图片可见、页面走通 |

分工可灵活调整，但先明确接口调用与数据样例。API 仓库维护接口/数据库脚本，Web 仓库维护 Vue 页面；需求、接口、中间件和进度文档以 API 为源同步。阶段表是剩余工作与验收顺序，不声明该阶段已完成；详细基线见 PROGRESS.md。

## 6. 最终验收清单

1. 空库按建表脚本初始化，不需要预置用户；用内部接口上传图片、录入店铺和普通/抢购商品，首页、分类、商品详情可见。
2. 验证码登录、新手机号注册、token 续期、退出和修改资料可用；未登录与错误内部口令返回接口文档规定的 401/403。
3. 普通单和抢购单同步返回可查询的订单 ID；抢购在时间窗外、库存不足、超过限购时返回正确业务码；取消未付抢购单回补库存。
4. 模拟支付生成券码，状态 `UNPAID → UNUSED → USED`；重复支付/核销不会重复计算；退款与超时/到期处理按第 4 节的状态规则执行。
5. Logstash 索引同步已确认，补录增量/店铺关联更新、重启及故障重放证据；Java 搜索能够读到最新的上架商品。RabbitMQ 生产/消费与失败处理单独验收，不因 Logstash 成功而记为完成；OSS 图片页面可见。
6. 用户网页走通：首页 → 搜索/详情 → 登录 → 下单 → 模拟支付 → 订单券码；Swagger 与原《接口文档》的全部 32 个接口、字段和错误码对应，最终不返回骨架期 501。
7. GitHub 修改走任务分支和 PR，由至少一名组员评审；真实数据库密码、OSS 密钥及 `.env` 不进入仓库。无并发吞吐、K8s、真实支付验收。
