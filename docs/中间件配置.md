# 抖省省仿制练手 · 中间件配置

> v2 · 2026-09-28
>
> 数据库和中间件都**不在本机**，由组员另行部署。本文列出后端对它们的全部要求：版本、服务端配置、库结构，以及后端的连接配置。库结构包括集合、索引、ES 索引、MQ 拓扑和 Redis key。
>
> 本文与实体类、`RedisKeys` / `MqNames` 常量、`application*.yml` 一一对应。
>
> **只建结构，不写任何数据**：
> - 4.7 节的建结构脚本只建集合、校验器和索引；
> - ES 只建索引；
> - 不建默认账号。
>
> 本文的所有配置都**没有实测过**，见第 12 节。

**版本依据**（2026-09-28 查询）：

- **Spring Boot**：3.5.16 是 3.5.x 的最新补丁版（Maven Central 2026-09-24 更新）。它托管的客户端版本，见 Spring Boot 3.5 的 Dependency Versions 页面。
- **springdoc**：CHANGELOG 显示，从 2.8.9 起跟进 Spring Boot 3.5；3.x 是给 Spring Boot 4 用的。
- **MongoDB**：官方驱动兼容表里，Java 驱动 5.2–5.7 对 MongoDB 8.0 全兼容（✓）；7.0 在 2026-08 已停止支持。
- **Elasticsearch**：
  - Spring Data Elasticsearch 5.5 的测试基线是 ES 8.18.1。
  - IK 插件版本必须和 ES 完全一致。检索到 IK 发布页上的最新版是 8.19.7，所以 ES 也选 8.19.7，而不是最新的 8.19.22。
  - 注意：8.19.7 这个结果来自检索，本机直连 IK 发布页失败过，部署前需要再确认一次。
- **Redis / RabbitMQ / Nginx**：取自 Docker 官方镜像清单 docker-library/official-images 里当前的标签。
- **FastDFS**：
  - V6.18.1 是官方仓库最新的 tag。它的 INSTALL 要求 libfastcommon V1.0.88 和 libserverframe V1.2.15。
  - fastdfs-nginx-module 用最新的 tag V1.26。

## 2. 应用配置（application*.yml）

后端在本机用 IDEA 运行。数据库和中间件的地址、口令全部通过环境变量传入，仓库里不放真实口令。

### 2.1 在 IDEA 里怎么配

1. 打开 Run/Debug Configurations → `DssApplication` → Environment variables，填 2.2 节的变量，至少把标了"必填"的都填上。
2. 要切换 profile，就加上 `DSS_PROFILE=prod`；不填默认是 dev。
3. **必填变量缺了，应用启动时会直接报 `Could not resolve placeholder`。** 这是故意的：宁可启动失败，也不要连错地址。
4. 暂时没有中间件、只想打开 Swagger 看接口时，必填变量填成任意格式合法的地址，应用也能启动：
   - Mongo、Redis、ES 都是用到时才连接；
   - RabbitMQ 连不上时，只会在后台重试并打日志；
   - 真正调接口时才会报错。
5. JDK 选 21。本机 IDEA 已经下载了 `ms-21.0.9`，路径是 `C:\Users\hp\.jdks\ms-21.0.9`。

### 2.5 两个 profile 的差别

两个 profile 的连接配置完全一样，都来自环境变量，写在公共的 application.yml 里。差别只在日志级别：

- **dev**（默认）：`com.dss` 包的日志级别是 debug。

## 3. 数据的通用约定

- **ID**：
  - 一律是 long，Mongo 的 `_id` 直接存 NumberLong。
  - 由 `RedisIdGenerator` 生成，见 5.4。
  - 接口 JSON 里一律是字符串。
- **金额**：long，单位是分。只有一个金额字段 `price`；订单里的 `amount` 等于下单时的 `price`。
- **时间**：
  - Java 里用 `LocalDateTime`，存成 BSON `date`。
  - 换算按 JVM 的默认时区进行。启动类里已经把默认时区固定为 Asia/Shanghai。
- **枚举**：存英文名字符串，如 `"ON_SHELF"`。
- **字段命名**：camelCase，和 Java 字段同名。
- **不写 `_class`**：`MongoConfig` 里关掉了 Spring Data 默认写入的 `_class` 字段。
- **null 不写入**：值为 null 的字段，Spring Data 默认不写入，文档里就没有这个字段。
- **索引的唯一真源是 4.7 的建结构脚本**：应用侧设了 `spring.data.mongodb.auto-index-creation=false`，实体类上不写 `@Indexed`。
- **校验器**（`$jsonSchema`）：
  - 只约束 required 和类型，不设 `additionalProperties:false`。
  - 可空字段的类型写成 `[类型, "null"]`。
  - 像"类型为 FLASH 时必填"这样的条件必填，由应用层校验。
- **类型对应**：

| Java | BSON |
|---|---|
| Long | long |
| Integer | int |
| String | string |
| LocalDateTime | date |
| List | array |
| 嵌套类 | object |

## 4. MongoDB（库名 dss）

### 4.1 部署要求

- **版本**：8.0.x。
- **必须以副本集运行。** 原因：抢购落单时"插入订单 + 扣库存"、取消时的回补，都要用多文档事务，而 MongoDB 的事务只能跑在副本集或分片集群上。
  - 练手用单节点副本集就够了。先用 `mongod --replSet rs0 --bind_ip_all` 启动，再在 mongosh 里执行一次：
    `rs.initiate({ _id: "rs0", members: [{ _id: 0, host: "<后端能访问到的地址>:27017" }] })`
  - 成员地址要写**后端能解析、能连上的地址**，也就是 IP 或域名，不要写容器名。否则驱动会按成员名去连，连接失败。
  - 如果成员地址实在改不了，就在连接串里加 `directConnection=true`。这个办法只适用于单节点。
- **鉴权**：
  - 要开启鉴权，并给应用建专用账号，只授予 dss 库的 readWrite 权限。
  - 副本集开鉴权时，还要配置 keyFile。
- **连接串示例**：`mongodb://dss:<口令>@10.0.0.5:27017/dss?replicaSet=rs0&authSource=admin`
- **建库结构**：执行 4.7 的脚本。它只建结构，不写数据。

### 4.8 坑与生产差异

- **事务管理器**：Spring Boot 不会自动配置 Mongo 事务管理器，项目在 `MongoConfig` 里手动声明了 `MongoTransactionManager`。
- **时区**：应用侧的 LocalDateTime 按 JVM 时区换算，所以各环境的 JVM 时区必须一致。启动类里已经固定为 Asia/Shanghai。
- **校验器**：校验器是 strict + error。字段类型不对的写入会被直接拒绝。例如 Integer 写成了 Long，就会被拒。
- **生产环境**：
  - 3 节点副本集，开鉴权 + keyFile；
  - 应用账号只给 dss 库的 readWrite；
  - 定期备份。

## 5. Redis

### 5.1 部署要求

- **版本**：7.4.x。
- **服务端配置**：

```
# 持久化：开启 AOF，每秒刷一次盘
appendonly yes
appendfsync everysec

# 内存上限与淘汰策略（原因见下）
maxmemory 256mb
maxmemory-policy noeviction

# 口令（后端用 DSS_REDIS_PASSWORD 传入同一个值）
requirepass <口令>
```

- **淘汰策略用 `noeviction`。** 抢购库存、已购数、ID 序列这几类 key 一旦被静默淘汰，就会导致超卖或重复 ID，所以宁可在内存满时让写入失败。
- **如果改用 Redis Cluster**：Lua 脚本用到的两个 key 必须落在同一个 slot 里，要给 key 加 hash tag，如 `dss:flash:stock:{123}`。当前的 key 设计是按单机或主从 Redis 写的。
- **生产环境**：主从复制，或者用托管 Redis；按业务量调大 maxmemory。

### 5.2 key 清单

- 统一前缀 `dss:`。
- key 和 value 都是字符串，读写用 `StringRedisTemplate`。
- key 的拼接方法都在 `com.dss.common.constant.RedisKeys` 里。

| key | 类型 | TTL | 内容 | 写入方 | 读取方 |
|---|---|---|---|---|---|
| `dss:login:code:{phone}` | string | 300 秒 | 6 位验证码 | 发验证码 | 登录 |
| `dss:login:code:interval:{phone}` | string | 60 秒 | 固定值 1，表示 60 秒内发过 | 发验证码 | 发验证码 |
| `dss:login:code:fail:{phone}` | string（计数） | 300 秒 | 当前验证码的校验失败次数，到 5 次作废 | 登录 | 登录 |
| `dss:login:token:{token}` | hash | 7 天，每次访问续满 | userId、nickname、avatar | 登录、修改资料 | 登录拦截器 |
| `dss:id:{biz}:{yyyyMMdd}` | string（计数） | 2 天 | 某个业务当天的 ID 序列 | RedisIdGenerator | RedisIdGenerator |
| `dss:flash:stock:{productId}` | string（整数） | 不过期 | 抢购剩余库存 | 新建/修改抢购商品、取消回补 | Lua 脚本、商品详情、抢购专区 |
| `dss:flash:bought:{productId}` | hash | 不过期 | field 是 userId，value 是已购数 | Lua 脚本、取消回补 | Lua 脚本 |
| `dss:lock:job:{jobName}` | string | 略短于任务间隔 | 定时任务锁 | 定时任务 | 定时任务 |

- `{biz}` 的取值：user、shop、product、order、favorite。
- `{jobName}` 的取值：order-timeout-fallback、voucher-expire。

### 5.3 Lua 脚本 flash_order.lua

位置：`dss-order/src/main/resources/lua/flash_order.lua`。骨架里只写了契约注释，还没有实现。

| 参数 | 含义 |
|---|---|
| KEYS[1] | 抢购库存 key `dss:flash:stock:{productId}` |
| KEYS[2] | 已购数 hash `dss:flash:bought:{productId}` |
| ARGV[1] | userId |
| ARGV[2] | limitPerUser |

| 返回值 | 含义 | 对应业务码 |
|---|---|---|
| 0 | 成功：库存 −1，该用户已购数 +1 | — |
| 1 | 库存不足 | 103010 |
| 2 | 超过限购 | 103011 |

时间窗由 Java 在调用脚本前校验：未开始是 103008，已结束是 103009。

### 5.4 ID 与券码

**ID 生成**（RedisIdGenerator，已实现）：

```
id = (当前秒 − 起始秒) << 32 | 当日序列
```

- 起始秒：`1767196800`，即 2026-01-01 00:00:00（东八区）。
- 当日序列：`INCR dss:id:{biz}:{yyyyMMdd}`。每个业务每天从 1 开始；第一次自增时，给 key 设 2 天过期。
- 位数分配：
  - 时间占高 31 位，大约够用 68 年；
  - 序列占低 32 位，每个业务每天最多约 42 亿个。
- 多副本部署也不用分配 workerId，因为序列在 Redis 里全局自增。
- 生成的 ID 是 17–18 位十进制数，超过了 JS 的 2^53，所以接口里一律用字符串。

**券码**：

- 12 位随机数字，支付时生成。
- 靠唯一索引 `uk_voucherCode` 保证全局唯一；插入冲突就重新生成一次。

## 6. RabbitMQ

### 6.1 部署要求

- **版本**：4.3.x，带 management 插件。项目不依赖延迟消息插件。
- **vhost 和账号**：
  - 建 vhost `/dss`，再给应用建一个专用账号。
  - 这个账号要有 `/dss` 的 configure、write、read 三项权限。交换机和队列都是应用启动时自己声明的，所以需要 configure 权限。
- **建议的服务端配置**：

```
# 内存用到 60% 时阻塞生产者
vm_memory_high_watermark.relative = 0.6
# 磁盘剩余少于 1GB 时阻塞生产者
disk_free_limit.absolute = 1GB
# guest 账号只允许从本机回环地址登录（这是默认值，写出来是为了明确）
loopback_users.guest = true
```

- **用容器部署时要固定 hostname。** RabbitMQ 的数据目录按节点名存放，主机名一变，重建容器后就找不到原来的数据。
- **生产环境**：3 节点集群，队列改用 quorum 类型。改队列类型的话，`OrderMqConfig`、`SearchMqConfig` 里的声明参数要一起改。

### 6.2 交换机

- 名称常量都在 `com.dss.common.constant.MqNames` 里。
- 拓扑由应用启动时的 Spring AMQP 声明，分布在 `OrderMqConfig`、`SearchMqConfig`、`RabbitCommonConfig` 三个类里。

| 名称 | 类型 | 持久化 | 用途 |
|---|---|---|---|
| dss.order.direct | direct | 是 | 订单：抢购落单、超时延迟、超时取消 |
| dss.search.topic | topic | 是 | 搜索同步 |
| dss.dlx | direct | 是 | 公共死信：业务队列重试 3 次仍然失败的消息进这里 |

### 6.3 队列与绑定

| 队列 | 绑定（交换机 / 路由键） | 队列参数 | 消费者 |
|---|---|---|---|
| order.flash.create | dss.order.direct / `order.flash.create` | DLX = dss.dlx，DLK = `order.flash.create.dlq` | FlashOrderConsumer |
| order.timeout.delay | dss.order.direct / `order.timeout.delay` | `x-message-ttl` = 900000（15 分钟，取自 `dss.order.pay-timeout-minutes`），DLX = dss.order.direct，DLK = `order.timeout` | **无**（专门等消息过期） |
| order.timeout | dss.order.direct / `order.timeout` | DLX = dss.dlx，DLK = `order.timeout.dlq` | OrderTimeoutConsumer |
| search.sync | dss.search.topic / `shop.*`、`product.*` | DLX = dss.dlx，DLK = `search.sync.dlq` | SearchSyncConsumer |
| order.flash.create.dlq | dss.dlx / `order.flash.create.dlq` | — | 无（人工处理） |
| order.timeout.dlq | dss.dlx / `order.timeout.dlq` | — | 无（人工处理） |
| search.sync.dlq | dss.dlx / `search.sync.dlq` | — | 无（人工处理） |

所有队列都是持久化队列。

**修改超时时长时要注意**：`order.timeout.delay` 的 TTL 是在声明队列时定下的。如果改了 `dss.order.pay-timeout-minutes`，要先在管理台删掉旧的 `order.timeout.delay` 队列，否则重新声明时参数不一致，会报 PRECONDITION_FAILED。

### 6.4 消息体（JSON）

| 消息类 | 所在模块 | 路由键 | 字段 |
|---|---|---|---|
| FlashOrderMessage | dss-order | order.flash.create | orderId(long)、userId(long)、productId(long)、createTime(时间) |
| OrderTimeoutMessage | dss-order | order.timeout.delay | orderId(long) |
| SearchSyncMessage | dss-common | shop.upsert / product.upsert | docType(SHOP / PRODUCT)、id(long) |

`SearchSyncMessage` 放在 common 模块里，因为 shop 和 product 模块都要发它，但它们不能依赖 dss-search。

### 6.5 可靠性

- **生产者**：
  - 开启了 `publisher-confirm-type: correlated`、`publisher-returns: true`、`template.mandatory: true`。
  - 消息没到达交换机，或者没路由到任何队列，都会记 ERROR 日志，见 `RabbitCommonConfig`。
- **消费者**：
  - 使用 auto ack，失败时本地重试 3 次，间隔从 1 秒起、每次翻倍。
  - 3 次都失败，就拒绝且不重新入队（`default-requeue-rejected: false`），消息进入这个队列的死信队列。
- **消息转换**：`Jackson2JsonMessageConverter` 复用应用的 ObjectMapper，时间格式和接口保持一致；只信任 `com.dss.*` 包下的类。

| businessHours | keyword，`index: false` | 营业时间 | shops.businessHours |
| createTime | date，`yyyy-MM-dd HH:mm:ss` | 创建时间 | shops.createTime |

### 7.4 建索引

把 7.2、7.3 的 JSON 分别存成 `dss_product.json`、`dss_shop.json`，然后执行下面的命令。它们只建索引，不写文档：

```
# 返回 200 表示索引已存在，跳过；返回 404 才执行下面的 PUT
curl -s -o /dev/null -w "%{http_code}" -I "http://<ES 地址>:9200/dss_product"
curl -X PUT "http://<ES 地址>:9200/dss_product" -H "Content-Type: application/json" --data-binary @dss_product.json

curl -s -o /dev/null -w "%{http_code}" -I "http://<ES 地址>:9200/dss_shop"
curl -X PUT "http://<ES 地址>:9200/dss_shop" -H "Content-Type: application/json" --data-binary @dss_shop.json
```

ES 开了安全认证时，再加 `-u <账号>:<口令>`，并改用 https 地址。

### 7.5 同步规则

- **事件内容**：事件只带 `docType` 和 `id`。消费者收到后从 Mongo 读最新数据，整条覆盖写入 ES，所以事件重复或乱序都不会写错。
- **店铺改名或改分类**：要把这家店所有商品文档里的 shopName、shopCategory 一起更新，按 shopId 批量更新。
- **商品下架**：不删文档，只更新 status；搜索时按 `status = ON_SHELF` 过滤。

## 8. FastDFS

### 8.1 版本

- 组件版本全部锁定：

| 组件 | 版本 |
|---|---|
| fastdfs | V6.18.1 |
| libfastcommon | V1.0.88 |
| libserverframe | V1.2.15 |
| fastdfs-nginx-module | V1.26 |
| storage 侧 nginx | 1.23.3（官方 Dockerfile 注释里推荐列表的最高版本） |

- 官方没有可以直接用的镜像，只在仓库的 `docker/dockerfile_network` 里提供了 Dockerfile。
- 那个 Dockerfile 的基础镜像是已经停止维护的 CentOS 7，自建时要换成仍在维护的系统，比如 Debian。
- 组成：
  - tracker 负责调度，端口 22122；
  - storage 负责存文件，端口 23000；
  - storage 旁边还要跑一个带 fastdfs-nginx-module 的 nginx，在 8888 端口按 fileId 读图。

### 8.2 关键配置

| 文件 | 关键项 |
|---|---|
| tracker.conf | `port=22122`、`base_path=/var/fdfs/tracker`、`store_lookup=2`（选剩余空间最多的组）、`reserved_storage_space=10%`、`storage_ip_changed_auto_adjust=true`（storage 的 IP 变了自动调整） |
| storage.conf | `group_name=group1`、`port=23000`，`base_path` 和 `store_path0` 都是 `/var/fdfs/storage`；`tracker_server=<tracker 的 IP>:22122`（这里必须写 IP）；`http.server_port=8888` |
| mod_fastdfs.conf | `tracker_server=<tracker 的 IP>:22122`、`storage_server_port=23000`、`group_name=group1`、`url_have_group_name=true`、`store_path0=/var/fdfs/storage` |

storage 侧 nginx 的配置：

```nginx
worker_processes 1;

events {
    worker_connections 1024;
}

http {
    include mime.types;
    default_type application/octet-stream;
    sendfile on;
    keepalive_timeout 65;

    server {
        listen 8888;
        server_name _;

        # fileId 形如 group1/M00/00/00/xxx.jpg
        location ~ /group[0-9]+/M00 {
            ngx_fastdfs_module;
        }
    }
}
```

### 8.3 fileId 与图片地址

- 数据库里只存 fileId，形如 `group1/M00/00/00/xxx.jpg`。
- 返回前端时，由 `FileUrlResolver` 拼成 `dss.file.base-url + "/" + fileId`。
- `dss.file.base-url` 可以不配（为空）。这时返回的是站点相对地址 `/group1/M00/...`，由第 9 节 Nginx 的 `/groupN/` 规则反代到 storage 的 8888 端口。
- 也可以直接配成图片域名，例如 `http://img.example.com`。

### 8.4 "容器 IP 问题"（最大的坑，未实测）

- **问题**：tracker 返回给客户端的，是 storage 注册时的 IP。
  - 如果 storage 跑在容器里，这个 IP 就是容器内网 IP（172.x）。
  - 后端不在同一个容器网络里时，能连上 tracker，但连不上 storage，上传会失败。
  - 读图不受影响，因为读图走的是 8888 端口。
- FastDFS 不允许把 `tracker_server` 配成 127.0.0.1，所以不能用回环地址绕过去。
- **可选的解法**（都没试过）：
  1. 后端和 FastDFS 放在同一个容器网络里；
  2. FastDFS 容器用 host 网络（`network_mode: host`），`tracker_server` 填宿主机的内网 IP；
  3. 直接在云主机或虚拟机上装 FastDFS，不用容器。
- **上 K8s 以后**：一般要 `hostNetwork: true`，并把 storage 固定在某个节点上。部署阶段再定。

### 8.5 Java 客户端（骨架里还没引入依赖，`FastDfsFileStorage` 是桩）

- tobato 的 `com.github.tobato:fastdfs-client` 最后一版是 1.27.2（2020-02）。它的基线是 Spring Boot 2.0，没有声明支持 Spring Boot 3 / Jakarta。
- 官方的 happyfish100/fastdfs-client-java 没有发到 Maven Central，只有第三方重打包的版本，最新的一个是 2023 年发布的。
- 实现阶段二选一：
  - 用重打包的版本，用之前先核对它的源码；
  - 或者用官方源码构建后再引入。

## 9. Nginx（前端托管与反代）

规则：

- **前端**：托管前端的构建产物，history 路由回退到 `index.html`。前端工程另建。
- **后端**：`/api/` 反代到后端 8080。
- **不对外的路径**：`/api/v1/internal/`、`/swagger-ui`、`/v3/api-docs` 一律 `deny all`，所以对外只暴露 C 端接口。
- **图片**：`/groupN/...` 这类图片路径反代到 FastDFS storage 的 8888 端口。
- **其他**：`client_max_body_size 10m`，开启 gzip。
- **用 K8s 时**：这一层可以换成 Ingress，规则照搬。

```nginx
worker_processes auto;

events {
    worker_connections 1024;
}

http {
    include /etc/nginx/mime.types;
    default_type application/octet-stream;
    sendfile on;
    keepalive_timeout 65;

    client_max_body_size 10m;

    gzip on;
    gzip_min_length 1k;
    gzip_types text/plain text/css application/javascript application/json image/svg+xml;

    # 部署时改成实际的地址
    upstream dss_backend {
        server <后端地址>:8080;
    }
    upstream dss_fdfs {
        server <FastDFS storage 地址>:8888;
    }

    server {
        listen 80;
        server_name _;

        # 前端构建产物
        root /usr/share/nginx/html;
        index index.html;

        # 内部接口和 Swagger 只能直连后端访问，对外一律拒绝
        location ^~ /api/v1/internal/ {
            deny all;
        }
        location ^~ /swagger-ui {
            deny all;
        }
        location ^~ /v3/api-docs {
            deny all;
        }

        location /api/ {
            proxy_pass http://dss_backend;
            proxy_set_header Host $host;
            proxy_set_header X-Real-IP $remote_addr;
            proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
            proxy_set_header X-Forwarded-Proto $scheme;
        }

        # 图片：fileId 形如 group1/M00/00/00/xxx.jpg
        location ~ ^/group[0-9]+/ {
            proxy_pass http://dss_fdfs;
        }

        # 前端 history 路由回退
        location / {
            try_files $uri $uri/ /index.html;
        }
    }
}
```

## 10. Swagger（springdoc）

- **地址**：`/swagger-ui.html`；OpenAPI JSON 在 `/v3/api-docs`。
- **分两组**：
  - "C 端接口"：`/api/v1/**`，不含 internal；需要登录的接口标了 bearerToken。
  - "内部接口"：`/api/v1/internal/**`，这一组全部要带 `X-Internal-Key`。
- **开关**：dev 和 prod 默认都开，因为生产环境录数据也要靠它；外网访问由 Nginx 挡住。开关是 `DSS_SWAGGER_ENABLED`。
- **录数据的顺序**：
  1. 先在"内部接口"组点 Authorize，填 `X-Internal-Key`；
  2. 上传图片，拿到 fileId；
  3. 新建店铺；
  4. 新建商品。

## 11. 常见坑汇总

1. **MongoDB 必须是副本集**，事务管理器要手动声明（4.1、4.8）。
2. **副本集成员地址要写后端能连上的地址**，不能写容器名；单节点实在改不了，就在连接串里加 `directConnection=true`（4.1）。
3. **FastDFS 容器 IP 问题**：后端不在同一容器网络时连不上 storage（8.4）。
4. **IK 插件版本必须和 ES 一模一样**（7.1）。
5. **ES mapping 是 strict 的**，Spring Data 的 `_class` 必须关掉（7.1）。
6. **RabbitMQ**：要固定 hostname；改延迟队列的 TTL 要先删旧队列；应用账号要有 configure 权限（6.1、6.3）。
7. **Redis 用 noeviction**：内存满了写入会失败，而不是悄悄丢掉库存（5.1）。
8. **必填环境变量缺了，后端启动就会失败**，这是故意的（2.1）。
9. **long ID 到了前端要当字符串用**，不能转成 Number（第 3 节）。
