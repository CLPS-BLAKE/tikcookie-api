# TikCookie 团购券平台 · 用户故事模型

> 依据《0928会议》草图整理，结合已确定的教学项目范围与现行《需求文档》《接口文档》。2026-09-29 更新：由用户在待使用订单中点击“去使用”完成模拟核销。图片是早期移动端草图，原有 MongoDB、FastDFS、K8s 等技术标记及视觉尺寸不作为本期实现要求；目标是 Vue 3 的 PC 网页、MySQL + MyBatis-Plus、OSS、单实例后端。图片中个别小字较模糊，下文按可辨认的流程和现行接口合同归纳，不把无法辨认的文字当成确定需求。

## 1. 产品目标、角色与主路径

**目标**：用户能找到适合的团购商品，购买一张团购券，在订单中点击“去使用”完成模拟核销；项目组员能录入演示商品并验证结果。支付、退款、核销均为教学模拟，不接真实交易渠道。

| 角色 | 想完成的事 | 可见入口 |
|---|---|---|
| 游客 | 浏览首页、搜索商品和店铺、查看详情 | 首页、搜索页、店铺页、商品详情 |
| 登录用户 | 下单、模拟支付、在订单中点击“去使用”、管理订单/收藏/资料 | 登录页或弹窗、确认订单、个人主页、订单详情 |
| 项目组员 | 上传图片、录入/上下架商品 | Swagger 的内部接口，不做商家后台页面 |
| 系统任务 | 取消超时未付单、处理已到期未核销券、更新搜索索引 | 后台自动执行，无用户页面 |

主路径：**浏览/搜索 → 商品详情 → 登录 → 提交订单 → 模拟支付 → 待使用订单 → 点击“去使用” → 已使用**。券码仍在订单详情展示，但本期核销不要求组员扫码或输入券码。用户还可以取消待支付订单、对未使用的券模拟退款，以及收藏商品/店铺。

## 3. 用户故事地图

| 活动 | 找到商品 | 了解商品 | 购买券 | 使用或处理券 | 回访与管理 |
|---|---|---|---|---|---|
| 用户任务 | 进入首页、按分类看、搜商品/店铺 | 看商品套餐、价格、规则、店铺信息 | 登录、确认普通或抢购订单、模拟支付 | 在待使用订单中点击“去使用”、取消/退款 | 看个人资料、收藏和历史订单 |
| 第一阶段 | `US-02` 首页，`US-03` 搜索入口 | 商品卡片和详情跳转骨架 | `US-01` 登录 | 个人主页订单入口 | `US-14` 基础资料 |
| 第二阶段 | 搜索结果与筛选联调 | `US-04` 商品详情、`US-05` 店铺详情 | `US-06` 普通下单、`US-07` 抢购下单、`US-08` 模拟支付 | `US-09` 取消/超时、`US-10` 订单查询、`US-11` 核销、`US-12` 退款/到期 | 个人主页显示真实订单 |
| 第三阶段 | 搜索体验收尾 | 详情页收藏状态 | — | — | `US-13` 收藏、`US-14` 头像资料完善 |

`US-15` 内部商品录入和图片上传是第一阶段浏览的前置条件；`US-16` 搜索同步与索引重建支撑搜索结果，在第一阶段接入基础搜索、第三阶段完成故障恢复验收。每阶段可以合并跨阶段的小任务，以可运行演示优先。

## 4. 故事清单与验收条件

优先级说明：**P0** 是购买团购券主链路，**P1** 是接口文档已承诺的配套功能。两者都属于本期 32 接口最终验收；优先级只决定开发顺序。

| ID / 优先级 | 用户故事（作为…我希望…以便…） | 最小验收条件 | 主要接口 |
|---|---|---|---|
| US-01 / P0 | 作为游客，我希望用手机号和验证码登录，以便购买团购券 | 可获取开发演示验证码；正确码登录，新号自动注册；错误或过期码被拒；token 失效须重新登录 | `POST /auth/sms-code`、`POST /auth/login` |
| US-02 / P0 | 作为游客，我希望在首页看到分类、最新商品和抢购入口，以便快速找到商品 | 分类可点；商品只展示上架项；点击卡片进入对应详情 | `GET /categories`、`GET /products`、`GET /products/flash` |
| US-03 / P1 | 作为游客，我希望输入关键词并筛选商品/店铺，以便缩小选择范围 | 商品与店铺可分别搜索；按接口约定分类/类型/价格/销量排序和分页；搜索故障有提示 | `GET /search/products`、`GET /search/shops` |
| US-04 / P0 | 作为游客，我希望看到团购商品的套餐、价格、图片和使用规则，以便决定是否购买 | 商品详情展示店铺、有效天数；抢购项还显示时间窗、剩余库存、限购；下架商品不可下单 | `GET /products/{productId}` |
| US-05 / P1 | 作为游客，我希望查看店铺信息和其在售商品，以便确认到店位置和选择套餐 | 店名、地址、图片可见；店内商品卡片可进入商品详情 | `GET /shops/{shopId}`、`GET /shops/{shopId}/products` |
| US-06 / P0 | 作为登录用户，我希望对普通商品提交订单，以便获得待支付记录 | 一单一商品；成功返回订单 ID，立即能在订单详情查询；订单保存购买时的名称和价格快照 | `POST /orders`、`GET /orders/{orderId}` |
| US-07 / P0 | 作为登录用户，我希望在时间窗内购买抢购商品，以便享受限量价格 | 未开始、已结束、售罄、超出每人限购时分别按接口业务码拒绝；成功扣减 MySQL 库存并立即生成订单 | `POST /orders/flash` |
| US-08 / P0 | 作为登录用户，我希望模拟支付待支付订单，以便获得可使用的券码 | 15 分钟内可支付；成功后状态为 `UNUSED`，产生唯一 12 位券码；重复支付不会重复计入销量 | `POST /orders/{orderId}/pay` |
| US-09 / P1 | 作为登录用户，我希望取消未支付订单，以便放弃购买 | 只有 `UNPAID` 可取消；抢购库存恢复、限购名额释放；过支付截止时间的未付订单由系统自动取消 | `POST /orders/{orderId}/cancel`；后台任务 |
| US-10 / P0 | 作为登录用户，我希望在个人主页查看订单列表和详情，以便找到待支付订单或券码 | 可按状态分页；只能看自己的订单；`UNUSED` 和 `USED` 详情可见券码 | `GET /orders`、`GET /orders/{orderId}` |
| US-11 / P0 | 作为登录用户，我希望在自己的待使用订单中点击“去使用”，以便完成本次模拟核销 | 仅本人、`UNUSED` 且未到期的订单显示可用按钮；点击后立即变成 `USED`，记录使用时间并刷新详情；非本人、过期、已使用、已退款均不能成功；券码只展示，不作为操作凭据 | `POST /orders/{orderId}/use` |
| US-12 / P1 | 作为登录用户，我希望退掉尚未使用的券，以便结束该笔模拟交易 | `UNUSED` 可模拟退款成 `REFUNDED`；到期未用自动退款；销量回退，抢购库存不回补 | `POST /orders/{orderId}/refund`；后台任务 |
| US-13 / P1 | 作为登录用户，我希望收藏店铺或商品，以便稍后查看 | 详情页能显示收藏状态；可收藏、取消和查看列表；重复收藏按接口业务码处理 | `POST /favorites`、`DELETE /favorites/{targetType}/{targetId}`、`GET /favorites`、`GET /favorites/status` |
| US-14 / P1 | 作为登录用户，我希望查看与修改个人资料、上传头像、退出登录，以便管理账号 | 昵称/头像修改后可见；头像可通过文件接口上传；退出后原 token 失效 | `GET/PUT /users/me`、`POST /files/images`、`POST /auth/logout` |
| US-15 / P0 | 作为项目组员，我希望用内部接口录入店铺、商品和图片，以便产生可购买的演示数据 | 内部口令有效才可操作；能上传 OSS 图片、新建/修改店铺商品和上下架；不建管理后台 | `POST/PUT /internal/shops`、`POST/PUT /internal/products`、`PUT /internal/products/{productId}/status`、`POST /internal/files/images` |
| US-16 / P1 | 作为用户，我希望搜索结果能反映商品变化，以便找到当前可购买内容 | 商品/店铺变更后通过 RabbitMQ 更新 ES；搜索只给上架商品；消息丢失后能从 MySQL 重建索引 | 搜索接口、内部维护任务 |

表中的接口路径省略共同前缀 `/api/v1`。接口的完整方法、参数、响应和错误码以本次修订的《接口文档》为准；`POST/PUT /internal/shops` 等写法仅是故事表的缩写，具体 URL 不可由表格推断。

## 5. 关键状态与故事关联

| 状态变化 | 触发故事 | 用户能观察到的结果 |
|---|---|---|
| 创建订单 → `UNPAID` | US-06、US-07 | 待支付订单和 15 分钟截止时间 |
| `UNPAID` → `UNUSED` | US-08 | 支付成功、券码可查看 |
| `UNPAID` → `CANCELLED` | US-09 | 用户取消或超时，抢购未付库存回补 |
| `UNUSED` → `USED` | US-11 | 用户点击“去使用”成功，不能再次使用或退款 |
| `UNUSED` → `REFUNDED` | US-12 | 用户申请或券到期后模拟退款 |

一笔订单只允许其中一条有效状态变化成功；列表和详情要显示同一结果。抢购退款后库存不回补，取消未付抢购单才回补。

## 7. 完成定义

- 前端能从首页走完整条主路径，后端订单与库存状态在 MySQL 可核对；不能仅做静态页面或返回固定假数据。
- 每条故事至少验证一条成功路径和一条关键失败路径；接口合同、页面提示及 Swagger 行为一致。
- 两个前端、两个后端和一位部署组员在每阶段用真实环境联调；部署员提供 MySQL、Redis、RabbitMQ、ES、OSS 和 Nginx 连接与检查结果。
- 最终核对《接口文档》的 32 个接口，不以图片上的简略字段替代现行接口字段；本项目没有吞吐或并发性能指标。
