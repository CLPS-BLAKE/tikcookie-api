# 测试与验收规范

## 1. 提交前最低检查

项目骨架确定后，每个 PR 至少执行：

- 编译
- 单元测试
- 应用打包
- 静态检查或格式检查（如项目启用）
- 涉及 MongoDB 或中间件时的集成测试

具体命令应写入 README，并由 CI 使用相同或等效命令。

## 2. 接口测试

接口功能至少验证：

- 正常请求
- 参数边界与非法输入
- 未登录和无权限
- 资源不存在与业务冲突
- 重复请求或幂等要求
- 异常时不会泄露内部信息

## 3. 中间件验收

| 组件 | 最低验收 |
| --- | --- |
| MongoDB | 核心业务数据可写入、查询并在容器重建后保留 |
| Redis | 至少一个真实业务功能命中缓存或状态存储 |
| RabbitMQ | 可观察商品变更消息的生产、消费及失败处理 |
| Elasticsearch | 关键词搜索使用真实索引，商品变更后结果更新 |
| OSS | 图片上传成功，页面可访问，密钥不暴露给客户端 |

## 4. 核心回归场景

- 登录和认证失败处理
- 商品新增、查询、更新与搜索同步
- 店铺与商品详情
- 订单创建和查询
- 图片上传与访问
- 应用重启后的数据恢复

## 5. PR 验证证据

PR 中记录执行的命令和结果。涉及接口时提供脱敏的请求/响应样例；涉及中间件时说明验证步骤和观察结果。若某项无法验证，应说明原因、风险和后续负责人。
