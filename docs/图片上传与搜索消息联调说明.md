| 接口 | 鉴权 | 用途 |
|---|---|---|

## 2. OSS 配置与读图方式

配置项在 `application.yml` 的 `dss.file.oss.*`，取值来自环境变量（本地放 `tikcookie-api/.env`）：

| 变量 | 说明 |
|---|---|
| `DSS_OSS_ENDPOINT` | 形如 `https://oss-cn-guangzhou.aliyuncs.com`（**必须带 `oss-` 前缀**） |
| `DSS_OSS_BUCKET` | 演示图片专用 Bucket |
| `DSS_OSS_REGION` | 形如 `cn-guangzhou` |
| `DSS_OSS_ACCESS_KEY_ID` / `DSS_OSS_ACCESS_KEY_SECRET` | 最小权限 RAM 用户；留空时改用环境变量 `OSS_ACCESS_KEY_ID` / `OSS_ACCESS_KEY_SECRET`（可选 `OSS_SESSION_TOKEN`） |
| `DSS_FILE_BASE_URL` | 图片公共读取前缀（末尾不带 `/`）。Bucket 公共读时填 OSS 公共域名 `https://<bucket>.oss-<region>.aliyuncs.com`（或自己的 CNAME 域名）；**留空时按 `DSS_OSS_ENDPOINT` + `DSS_OSS_BUCKET` 自动推导同一个域名**，所以本地/服务器都可以不填。填后端读图接口（本地 `http://127.0.0.1:8080/api/v1/images`、服务器 `https://<演示域名>/api/v1/images`）则改走后端代理 |

### 读图：Bucket 公共读，前端直连 OSS

`blake-tikcookie` 已开**公共读**（禁止匿名写，写入仍只用后端凭据），所以返回给前端的 `url` 直接指向 OSS 公共域名，
游客和登录用户用 `<img src>` 就能看到图，不需要 token，也不占后端带宽：

```
上传接口返回 {fileId, url}
  → url = dss.file.base-url 或（未配置时）推导出的 https://{bucket}.{endpoint-host}
  → 浏览器 GET {url} 直达 OSS（匿名可读）
```

- 拼接只由 `FileUrlResolver` 负责：**前端直接用接口返回的 `url`，不要自己拼地址**。
- 本地 `.env` 和服务器环境变量都把 `DSS_FILE_BASE_URL` 指向 OSS 公共域名，或者干脆留空让它自动推导
  （留空更适合换 Bucket / 换地域时少改一处）。
- 上传的对象名仍由后端生成（`ObjectKeys.generate`），前端无法构造别人的 `fileId`；但公共读意味着**任何拿到
  `fileId` 的人都能看图**，所以只放可公开展示的头像/商品图。
- `<img src>` 不受 CORS 限制；如果前端要用 `fetch` / WebGL 读像素，需要在 Bucket 上加 CORS 规则放行前端域名。

### 备用路径：Bucket 收紧为私有读时的后端代理

保留后端代理读图接口，Bucket 一旦改回私有读，只要把 `DSS_FILE_BASE_URL` 改回后端地址即可，前端无需改动：

```
浏览器 GET {DSS_FILE_BASE_URL}/{fileId}
  → FileController#readImage（公开，带不了 token 的 <img src> 也能用）
  → FileStorageService#loadImage 用后端凭据从 OSS 取流
  → 原样写回字节流：Content-Type 取对象里存的类型
     + Cache-Control: public, max-age=31536000, immutable
     + ETag（命中 If-None-Match 返回 304）
```

要点：

- 读图接口是公开的（`<img src>` 发不出 Authorization 头）。安全性靠：ObjectKey 是 32 位随机十六进制、
  不可枚举；图片本身是可公开展示的头像/商品图。要放敏感图片得改成签名 URL 或加鉴权，不在本期范围。
- 代理读图占用后端出口带宽；演示规模足够。要抗量可在后端前面挂 CDN，让 CDN 回源到这个读图接口。
- 服务器的 Nginx 只要按现有 `/api` 规则转发到后端即可，不需要为图片单独加 location。

## 3. ObjectKey 约定（业务方接入必读）

- 生成：`ObjectKeys.generate("jpg"|"png"|"webp")` → `group1/M00/00/00/{32 位十六进制 uuid}.{后缀}`。
  路径形式沿用《接口文档》示例的历史 FastDFS 风格（只是 OSS 上的字符串，不部署 FastDFS），
  **不使用用户上传的原始文件名**，避免重名覆盖与路径穿越。
  `ObjectKeys.DIRECTORY` 是**不带结尾 `/`** 的 `group1/M00/00/00`（斜杠由 `generate` 统一补）：
  写成 `"group1/M00/00/00/"` 会生成 `...//xxx.png` 这种带空路径段的 key，
  URL 被 CDN/代理规范化成单斜杠后取不到图（已加断言锁住，`ObjectKeysTest`）。
- 存储：库里只存 ObjectKey（即接口里的 `fileId`），**不存完整 URL**；展示时用
  `FileUrlResolver.toUrl(fileId)` 拼成 `图片公共前缀 + "/" + fileId`（前缀取 `dss.file.base-url`，
  未配置时按 `dss.file.oss.*` 推导 OSS 公共域名）。
- 校验：写库前调用 `ObjectKeys.requireValid(fileId)`；它拒绝空值、外部 URL（`http(s)://`、`//`）、
  本地路径、`..` 穿越、错误目录与错误后缀，非法时抛 `400 / 40000`。
  只需要判断不抛异常时用 `ObjectKeys.isValid(fileId)`。
- 前端流程：先调上传接口拿 `fileId` → 再把 `fileId` 提交给业务接口。
  业务接口**不要**接受前端给的外部图片地址。

```java
// shop / product / user 写库前
String image = ObjectKeys.requireValid(dto.getImage());   // 非法直接 400
entity.setCover(image);
```

## 4. 上传规则与错误码

上传校验顺序：**非空 → 大小 → 后缀 + 文件头魔数（两者必须一致）**。

| 情况 | HTTP | code | msg |
|---|---|---|---|
| 空文件 | 200 | 106001 | 文件为空 |
| 后缀或真实内容不是 jpg/png/webp（含伪装图片、内容与后缀不一致、`dss.file.allowed-types` 未包含） | 200 | 106002 | 只支持 jpg、png、webp 图片 |
| 超过 `dss.file.max-size`（默认 5MB） | 200 | 106003 | 文件超过大小限制 |
| OSS 上传失败 | 200 | 106004 | 文件上传失败 |
| 请求整体超过 10MB（`spring.servlet.multipart`） | 400 | 40000 | 上传的文件太大 |
| 缺少 file 部分 / multipart 无法解析 | 400 | 40000 | 缺少请求部分：file / 上传请求格式不正确 |
| 未带 token 调 C 端上传 | 401 | 40100 | 未登录或登录已过期 |
| 内部口令缺失或错误 | 403 | 40300 | 内部口令错误 |

读图（`GET /api/v1/images/{fileId}`）的错误：

| 情况 | HTTP | code | msg |
|---|---|---|---|
| fileId 格式不合法（外部 URL、穿越、短文件名等） | 404 | 40400 | 图片不存在 |
| 对象在 OSS 里不存在 | 404 | 40400 | 图片不存在 |
| Bucket 权限/配置有问题（如 AccessDenied） | 404 | 40400 | 图片不存在（真实原因在服务端 ERROR 日志里） |
| `If-None-Match` 命中 ETag | 304 | — | 无响应体，浏览器用本地缓存 |

读图不区分"没有这张图"和"存储侧出错"，避免向匿名请求暴露 Bucket 名、权限和 OSS 错误码。

类型判断以**文件头魔数**为准（JPEG `FF D8 FF`、PNG `89 50 4E 47 0D 0A 1A 0A`、WEBP `RIFF....WEBP`），
客户端声明的 `Content-Type` 只作参考；写入 OSS 的 `Content-Type` 用识别结果，读图时原样回给浏览器。

## 5. 搜索同步消息接入（shop / product）

```java
// 在 @Transactional 业务方法里直接调用即可
shopService.update(dto);
searchSyncPublisher.publishShopChanged(shopId);      // 提交成功后才会真正发出
searchSyncPublisher.publishProductChanged(productId);
```

- 交换机 `dss.search.direct`，路由键 `shop.changed` / `product.changed`；
  消息体 `{"type":"SHOP|PRODUCT","id":"123"}`，**id 是字符串**。
- 事务内调用：`afterCommit` 才发送；**事务回滚不发**；没有事务时立即发送。
- 发送失败只记 ERROR 日志（含 exchange、routingKey、type、id、correlationId），不向调用方抛异常——
  此时 MySQL 已提交，抛异常会让业务方误判整个操作失败。目标用全量重建补偿丢消息，本期不做 outbox。
  当前 `SearchService.rebuildAll` 仍是桩，不能直接启用 `DSS_SEARCH_REBUILD_ON_STARTUP=true` 作为已可用恢复手段。
- 消息只带类型与 ID，消费实现必须按 ID 读 MySQL 当前值，避免重复/乱序造成旧数据覆盖；当前 sync 仍是桩，不能据此声称 ES 已更新。

> **注意 `com.dss.*` 这个坑**：`RabbitCommonConfig` 里的 `trustedPackages` 必须是
> **消息类所在的包名**。原来写的 `"com.dss.*"` 匹配不到 `com.dss.common.mq.SearchSyncMessage`
> （Spring AMQP 按包名精确匹配，不是通配前缀），消费端反序列化会直接报
> `The class 'com.dss.common.mq.SearchSyncMessage' is not in the trusted packages`。
> 已改为 `"com.dss.common.mq"`，并加了不连中间件的回归用例 `RabbitCommonConfigTest`。
> 以后新增消息类时，记得把它的包名一并加进去。

## 6. 本地运行与验收

- **JDK 21 必需**（`pom.xml` 的 `java.version=21`）。若 `JAVA_HOME` 指向 JDK 17，`mvn package` 会报"不支持发行版本 21"。
- 构建与测试（`tikcookie-api` 目录下，`.env` 已配好时可连同真机联调一起跑）：

```powershell
$env:JAVA_HOME='C:\Program Files\Java\jdk-21'
mvn -B clean package
```

- 不依赖中间件的用例（响应/异常/鉴权/分页/序列化/ObjectKey/图片 URL 拼接/上传校验/读图契约/消息发布/可信包）默认全部运行；
  需要真机的两个用例在缺少 `.env` 时自动跳过：
  `OssFileStorageLiveTest`（真实上传 + 预签名回读 + loadImage 真实取流 + 匿名直连 url 能取回原图 + 删除）、
  `SearchSyncPublisherRabbitLiveTest`（真实交换机路由 + 线上 JSON + 提交前/回滚无消息）。
- 手动验收步骤：启动后端 → 调内部上传接口拿 `fileId` 和 `url` → **用浏览器直接打开返回的 `url`**
  （公共读下应是 `https://<bucket>.oss-<region>.aliyuncs.com/group1/M00/00/00/xxx.png`，
  不登录、不带 token 就能看到图片本身）→ 把 `fileId` 传给业务接口保存 →
  重新查询确认图片仍能显示；商品变更后到 RabbitMQ 管理台看 `dss.search.sync` 的投递与 `dss.search.dlq` 是否为空。

## 7. 历史局部验证记录与遗留问题

下列为本文已有的真实环境局部验证记录，本次文档更新未重新执行，不代表全部业务链路或当前 main 已通过：

- 内部上传真实 PNG → `code=0`，返回真实 ObjectKey；对象确实落在 Bucket 里，`Content-Type=image/png`，
  预签名 URL 可下载到与上传完全一致的字节，删除后对象消失。
- 读图（`loadImage`）从真实 Bucket 取回的字节、Content-Type、长度与上传完全一致；不存在的对象返回 404。
- **Bucket 已开公共读**：不带任何凭据裸访问 OSS 公共域名（上传返回的 `url`）返回 200 和原图字节，
  与预签名 / 代理读图结果一致；配合 `FileUrlResolver` 推导出的域名一起验证通过。
- C 端上传无 token / 假 token → 401 / 40100；内部上传错误口令、缺失口令 → 403 / 40300。
- 伪装图片 → 106002；空文件 → 106001；6MB → 106003；11MB → **HTTP 400 + 40000**；缺 file 部分 → 400 + 40000。
- Swagger 两组 api-docs 均 200；公开接口无需 token。

遗留 / 待办：

1. **读图接口的登记**：它作为额外实现补充，不计入原 32 条，正式清单扩展另行评审；前端默认直连 OSS。
2. **跨模块联调**：user/shop/product/order 已有实现，头像与店铺/商品图片绑定仍需真实页面验收；search.sync/rebuildAll 和搜索查询仍是桩，收藏也未实现，不能把上传成功当成网页闭环通过。
3. **公共读的边界**：`fileId` 是 32 位随机十六进制、不可枚举，但公共读下**知道地址就能看图**，
   所以 Bucket 里只放可公开展示的头像/商品图；要放敏感图片就得改签名 URL 或加鉴权，或把 Bucket 收回私有读并
   把 `DSS_FILE_BASE_URL` 指回后端代理接口。
4. `.env` 里 OSS endpoint 与本说明不一致时以本说明为准；服务器/CI 的环境变量由部署方核对。
