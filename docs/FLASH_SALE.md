# 抢购技术说明

按远端 main `e79f349` 源码整理。本文保留抢购设计和边界，不保留临时分支的测试统计。代码已实现不等于已测试或已部署。普通用户见 [使用指南](FLASH_SALE_USER_GUIDE.md)。

## 架构与状态

```text
登录用户 → API → Redis Lua 原子预占 → RabbitMQ → 消费者 → MySQL 事务建单
                    ↑                                  │
                    └──── 提交后确认或核对后幂等释放 ────┘
```

Redis 保存本轮、展示索引、商品资料、库存、额度和请求绑定。MySQL 保存商品与订单事实。RabbitMQ 解耦受理与建单，并发送支付超时消息。Java 商品搜索只返回 NORMAL，抢购展示不走 ES。

Redis 库存是可预占库存，MySQL 库存是建单后的剩余库存，排队期间可能不同。不能直接以一份覆盖另一份。跨 Redis、MQ、MySQL 不构成一个原子事务。

- 提交结果 PROCESSING：有请求绑定，不证明订单已创建。
- 查询结果 CREATED：当前查到本人数据库订单，仍须读取真实状态。
- 查询结果 NOT_CREATED：此刻未查到本人订单，不证明请求已终止或额度已释放。
- Redis 内部请求状态包括 PENDING、CREATED、TERMINATED、CANCELLED，不直接作为用户结果接口的失败原因返回。

## 正常流程

1. 客户端保存 requestKey，提交 productId 和原请求键。相同购买意图重试必须复用键。
2. Lua 校验本轮、资料完整性、活动、库存、额度，原子预占并绑定字符串订单号。
3. 只有新预占发送建单消息。同键重试返回原绑定，不重复投递或延长期限。
4. 消费者在商品协调锁内核对请求和期限，在 MySQL 事务中复核状态、扣库存并创建订单。
5. 提交后确认 Redis；遇到不确定结果先锁定并当前读数据库核对，无法核对则暂停商品、保留预占。
6. 客户端查询本人结果。CREATED 后取订单详情，按状态和 payDeadline 决定能否支付。

首次预占期限为 30 秒，扫描和核对可能延迟，不承诺第 30 秒恰好释放。支付期限默认建单后 15 分钟。支付生成券码，使用和退款为教学模拟。

## 库存、额度和销量

| 事件 | Redis 预占库存 | MySQL 库存 | 个人额度 | 销量 |
| --- | --- | --- | --- | --- |
| 新预占 | 减一 | 不变 | 占一个 | 不变 |
| 提交建单 | 不再扣 | 减一 | 保持 | 不变 |
| 同键重试/重复消息 | 不重复变化 | 不重复变化 | 不重复变化 | 不变 |
| 确认未建单并终止 | 幂等释放 | 不变 | 释放 | 不变 |
| 未付取消/支付超时取消 | 数据库提交后幂等释放 | 加一 | 释放 | 不变 |
| 支付 | 不变 | 不变 | 保持 | 加一 |
| 用券 | 不变 | 不变 | 保持 | 不变 |
| 用户退款/到期退款 | 不变 | 不变 | 不释放 | 减一 |

取消后 Redis 更新失败，数据库已取消结果仍有效，商品暂停等待核对。不能重复加数据库库存。订单状态见 [需求文档](需求文档.md)。

- 到点首次上架；售罄隐藏展示，活动中取消回补后可恢复。人工下架不被反复自动恢复，旧轮或结束商品不恢复售卖。

## MQ、任务和单实例限制

默认 MQ 前缀 dss.flash。主要资源为 `dss.flash.direct`、`dss.flash.orders`、`dss.flash.payment.wait` 和 `dss.flash.payment.timeout`。独立消费者为单消费者、prefetch=20、手动 ACK，不继承全局重试。重复投递仍需幂等保护。

支付等待队列 TTL 固定 900000 毫秒，不随 `DSS_ORDER_PAY_TIMEOUT_MINUTES` 自动变化。消费再次检查截止时间，数据库扫描兜底；支付接口也拒绝超期请求。订单扫描需显式核对 `DSS_JOB_ENABLED`。

当前只支持一个后端实例。商品协调锁为 256 个 JVM 分片锁，不是分布式锁。新订单使用固定节点的雪花 ID，部署须校时，不承诺跨实例或大幅时钟回拨后的发号恢复。

Redis 请求、释放标记不按 30 秒自动删除，需评估长期容量。Redis 丢失时没有同步 MySQL 抢购降级或自动重建交易缓存，不是 Redis Cluster 方案。

## 故障核对与验证

先暂停新购买，用受控工具核对 MySQL 订单、Redis 请求绑定/库存/额度和 MQ 日志。无法读取不等于没有订单。已有订单不能按未建单释放，不直接删请求标记或手工加库存。重启会核对旧请求并追加新轮，不是原活动无损续跑。

按 [TESTING.md](TESTING.md) 验证本人隔离、同键重试、限购、库存、重复消息、取消回补、超时、到期退款和故障暂停。只在隔离环境测试，不清业务库、Redis 或全局队列。本轮未运行这些验证，也不引用基线仓库中不存在的集成脚本。

核心源码位于 `src/main/java/com/dss/flash/`、`src/main/resources/lua/`、`OrderServiceImpl` 和 `ProductServiceImpl`。接口统一见 [接口文档](接口文档.md)，部署见 [DEPLOYMENT.md](DEPLOYMENT.md)。
